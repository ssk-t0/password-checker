# password-checker 🔑🎀

**「このパスワード、どれくらい強い？」を、見て・試して・学べるWebアプリ。**

React × TypeScriptで作った、パスワード強度チェッカーです。
強さを判定するだけでなく、推測されやすい部分や、攻撃環境による推定突破時間の違いまで見えるようにしました。

ちょっぴりハッカー気分になれるターミナル演出と一緒に、パスワードを守る仕組みを学べます🫶

## 🌷 できること

| 機能 | わかること・できること |
| --- | --- |
| 🔑 パスワード強度チェック | 0〜4のスコアと5段階の表示で、推測されにくさを確認 |
| ⏳ 推定突破時間の比較 | オンライン・オフラインなど、4つの条件で時間を比較 |
| 💻 攻撃シミュレーター | ターミナル風のログと全画面アニメーションで解析過程を演出 |
| 💬 改善アドバイス | 評価に応じた説明と、具体的な警告・改善案を日本語で表示 |
| 🧩 弱点の色分け ✨追加 | 辞書単語・連番・繰り返しなどを、部分ごとに確認 |
| 🔎 漏洩チェック ✨追加 | 既知の流出データに同じパスワードが含まれるか照合 |
| 🌸 日本語辞書 ✨追加 | 日本語の単語や人名を含む辞書も使って分析 |
| 🪄 パスワード生成 ✨追加 | ランダム文字列や、英単語をつなぐパスフレーズを生成 |
| 🧂 ハッシュとソルトの実験 ✨追加 | ソルトによる値の変化と、ハッシュ処理の速度差を体験 |

> このアプリは学習用です。実際に使用中のパスワードではなく、テスト用の文字列で試してください。アニメーションは演出で、実際の侵入や攻撃は行いません。

## 🪄 まずはこんな順番で遊んでみてね

1. **テスト用のパスワードを入力**するか、「パスワードを自動生成する」を開きます。
2. **「設定して攻撃シミュレーション開始」**を押します。
3. 解析が終わったら、**強度・改善アドバイス・4つの推定突破時間**を見比べます。
4. **「どこが推測されやすいか」**を開いて、文字列の特徴を確認します。
5. 気になったら、**漏洩チェック**や**ハッシュとソルトの実験**も試してみてください。

全画面の演出は「演出を閉じる ×」で閉じられます。入力を変えると解析はリセットされるので、文字数や単語を変えて比較できます。

## 🎀 追加機能をもう少し詳しく

### 🧩 「どこが弱いの？」を色分け

「弱い」と言われるだけでは、どこを変えればよいか迷いますよね。
そこで、zxcvbn-tsの分析結果を使い、パスワードを部分ごとに分けて表示しました。

| 色 | 検出した特徴 |
| --- | --- |
| 🔴 赤 | 辞書単語・よく使われるパスワード |
| 🟠 オレンジ | 繰り返し・連番・キーボード配列・決まった単語の並び |
| 🟡 黄 | 日付・西暦 |
| 🟢 緑 | 分析上、総当たりとして評価された部分 |
| ⚪ グレー | 区切り文字 |

**緑だから必ず安全、という意味ではありません。** 全体の長さや、ほかの部分も含めて評価を見てください。
入力欄が非表示モードのときは、この画面の文字も伏せて表示します。

### 🔎 過去の流出データと照合

「漏洩データと照合する」を押すと、Have I Been PwnedのPwned Passwords APIに問い合わせます。

パスワードそのものを送らず、次の流れで照合しています。

1. ブラウザ内で、入力をSHA-1ハッシュに変換。
2. **ハッシュの先頭5文字だけ**を送信。
3. 同じ先頭5文字を持つ候補を受信。
4. 残りの部分が一致するかを、**ブラウザ内で確認**。

リクエストには`Add-Padding`ヘッダーも付けています。問い合わせはボタンを押したときだけ行い、入力のたびに送信することはありません。

「見つからなかった」は、照合先の既知のデータに一致がなかったという意味です。安全性や未流出を保証するものではありません。

### 🌸 日本語の単語・人名も分析

英語・共通辞書に加えて、`@zxcvbn-ts/language-ja`の辞書を追加しました。
日本語の単語や人名を含むパターンも分析対象にし、ライブラリが返す警告や改善案も日本語で表示しています。

### 🪄 自分で考えなくても、パスワードを生成

| モード | 選べる設定 |
| --- | --- |
| ランダム文字列 | 8〜32文字。小文字・大文字・数字・記号から、使う文字の候補を選択 |
| パスフレーズ | ランダムに選んだ英単語を、ハイフンで3〜7語つなぐ |

生成後は**「これを使う」**で入力欄に反映。そのまま強度チェックへ進めます。

乱数には`crypto.getRandomValues()`を使い、文字や単語を選ぶ際の偏りを避ける処理も入れました。選択した文字種は候補に含まれますが、すべての種類が必ず1文字以上入る仕様ではありません。

画面の「ビット数」は、生成条件から計算した候補数の目安です。zxcvbn-tsの強度スコアとは計算方法が異なります。

### 🧂 ハッシュとソルトを体験

ハッシュは、入力から計算する一定の長さの値。ソルトは、ハッシュ化するときに加えるランダムな値です。

この画面では、同じ入力について次の違いを確認できます。

- **ソルトなし：** 入力が同じなら、SHA-256の値も同じ。
- **ソルトあり：** 「ソルトを作り直す」を押すと、同じ入力でも値が変化。
- **速度比較：** SHA-256と、反復回数10万回のPBKDF2（SHA-256）をブラウザで実測。

「同じパスワードでも、処理の仕方でこんなに変わるんだ！」を体験するための機能です。
計測結果は端末やブラウザによって変わり、攻撃者の機材での速度を示すものではありません。ここでのソルト付きSHA-256やPBKDF2の設定は、仕組みを比較するための学習用実装です。

## ⏳ 4つの推定突破時間

| シナリオ | 想定している環境 |
| --- | --- |
| オンライン攻撃・制限あり | ログインの試行回数に制限がある |
| オンライン攻撃・制限なし | ログインの試行回数に制限がない |
| オフライン攻撃・低速ハッシュ | 流出したハッシュを、比較的遅い処理で照合する |
| オフライン攻撃・高速ハッシュ | 流出したハッシュを、高速な処理で照合できる |

表示はzxcvbn-tsの仮定に基づく推定値です。4種類の攻撃プログラムを実行しているわけではなく、実際の突破時間を保証するものでもありません。

このアプリが主に扱うのは、パスワードの**推測されやすさ**です。フィッシングや、流出した認証情報の使い回しなど、あらゆる攻撃への耐性を診断する機能ではありません。

## 🫧 データの扱い

強度分析・パスワード生成・ハッシュ計算はブラウザ内で行います。入力したパスワードを、このアプリがデータベースやブラウザの永続ストレージへ保存する処理はありません。

外部通信を行うのは、漏洩チェックのボタンを押したときです。Pwned Passwords APIへハッシュの先頭5文字を送ります。パスワード全文やハッシュ全文は送信しませんが、完全にオフラインで動く機能ではありません。

## 🏠 ローカルで動かす

Node.jsとnpmを用意して、ターミナルで実行します。

```bash
git clone https://github.com/ssk-t0/password-checker.git
cd password-checker
npm ci
npm run dev
```

表示されたローカルURLをブラウザで開けば準備完了です✨
Web Crypto APIを使う機能は、`localhost`またはHTTPS環境で試してください。漏洩チェックにはインターネット接続が必要です。

```bash
npm run build    # 公開用ファイルをdistへ出力
npm run preview  # ビルドした内容をローカルで確認
npm run lint     # コードの静的チェック
```

## 📖 作ったきっかけと、学んだこと

以前から気になっていたReactとTypeScript。「難しそう…」と思っていましたが、小さなアプリを作りながら触ってみることにしました。

基本は自分でコードを書いて試行錯誤し、分からないところはチャッピーに相談するスタイルです。型の不一致を開発中に教えてくれるTypeScriptには、何度も助けられました🫶

最初は強度チェックとターミナル演出が中心でしたが、「どこが弱いの？」「どう作ればいいの？」「サービス側はどう守るの？」という疑問から、5つの機能を追加しました。

今回、手を動かしながら学べたことはこちらです。

- Reactのコンポーネント・`useState`による状態管理・propsの受け渡し
- TypeScriptの型と、JavaScriptとの違い
- Node.js・npm・Viteの役割と、外部ライブラリの利用
- `fetch`と`async/await`によるAPI通信
- Web Crypto APIによる乱数生成とハッシュ計算
- ハッシュの一部だけで照合する仕組みや、ソルト・反復処理の考え方
- CSSによる画面づくりとアニメーション

**攻撃する側の仕組みを知ると、守る側の工夫も理解しやすくなる。**
そんな発見が、この制作でいちばん印象に残っています。

まだ学び途中ですが、「動いた！」のうれしさと「どうして？」の好奇心を大切に、少しずつ理解を深めていきたいです🌷
